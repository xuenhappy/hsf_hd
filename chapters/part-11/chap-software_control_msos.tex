\section{面向约束的编程：从几何隐喻到运行时契约}
\label{sec:section_2467}

传统过程式程序善于表达确定步骤，声明式程序善于表达目标与约束，连续求解器善于处理随时间变化的状态；智能运行时需要三者协作，而不是用其中一种消灭其余两种。我们把一次可部署程序定义为
\[
\mathcal P=(\mathcal X,\mathcal U,\mathcal O,G,C,J,\Pi,\mathcal V),
\]
其中 $\mathcal X$ 是带版本的状态空间，$\mathcal U$ 是输入与工具动作类型，$\mathcal O$ 是可观测输出类型，$G$ 是任务依赖图，$C$ 是硬约束集合，$J$ 是可比较的软目标向量，$\Pi$ 是执行策略，$\mathcal V$ 是验证器集合。离散执行索引为 $k\in\mathbb N$，时间戳为 $t_k$，步长 $\Delta t_k>0$。程序可以调用图搜索、神经网络、数据库、ODE 求解器或人工审批；这些后端是否“几何”并不改变契约语义。面向几何编程在这里被限定为适合表达邻接、距离、连续状态和局部约束的一种专用方式。

这里的可部署还意味着每个对象都有序列化模式和兼容规则。输入字段缺失、单位不符或版本过新时，系统应在准入阶段拒绝，而不是由下游模型猜测；输出只有通过模式、来源和业务谓词三重检查后才可成为外部动作。对于无法完整观测的状态，契约显式保存未知与置信区间，禁止用默认零值伪造确定性。这些看似普通的软件条件，正是把抽象动力学变成可重复运行实例所必需的桥梁。

程序不是哈密顿量。只有当状态具有辛结构、动力学确由哈密顿方程描述且数值积分器保持相应结构时，哈密顿量才是合适模型。一般任务更常写成受约束更新
\[
x_{k+1}=F_{\theta_k}(x_k,u_k,a_k;G_k),\qquad
a_k\in\arg\min_{a\in\mathcal A_k}J_k(x_k,a)
\quad\text{s.t.}\quad C_k(x_k,a)\le 0.
\]
若目标 $J_k$、结构 $G_k$、输入 $u_k$ 或约束 $C_k$ 改变，它们必须进入下一步，不能沿用旧势能面的最优性结论。求解器返回“可行”只表示满足已编码约束，不表示遗漏的现实条件也被满足；目标下降也不等于任务成功。运行时因此保存规范版本、输入来源、求解器版本、随机种子、容差和验证结果。

所谓“变量即场”也需类型化。标量、向量、概率分布、图节点属性、边流量和事件日志属于不同空间。若在单纯复形上使用离散微分形式，$0$-余链可以存放节点量，$1$-余链可以存放有向边量，关联矩阵把二者联系起来；但语义属性并不因为存到顶点就成为“质”，关系也不因为存到边上就自动成为“形”。局部结构网络记录对象身份、依赖和可达性，全局分布表示提供相似性、上下文和不确定度；二者通过任务身份键、绑定映射、耦合算子和读出接口联合。编译器检查类型、维度、权限和单位，不检查形而上本体。

例如机器人绕过障碍搬运药品，可声明目标位置、碰撞禁区、载荷上限、电量下限和交付时限。连续规划器负责轨迹，离散状态机负责取货与交付，Boundary 决定哪些地图可信，验证器检查碰撞和药品身份。地图更新后旧轨迹必须重验；电量估计失准时，即使路径代价更低也不能提交。几何描述有用，因为空间距离与障碍确是领域对象，但证明来自约束求解和实测，而不是“最小作用量”一词。该范式的价值是把意图、假设和验收接口放进同一份可执行契约，同时保留传统代码对异常、事务与权限的精确控制。

契约还必须描述不成功的路径。我们把一次执行划分为 admitted、running、suspended、committing、completed、failed 与 compensated 等状态；每次转换都列出前置条件、可见副作用和补偿动作。以药品搬运为例，机器人到达药房却拿错批次，位置目标已经满足，任务仍然失败；扫码正确但门禁授权在途中被撤销，已有规划也必须挂起。若执行器已经抓取药品而数据库事务提交失败，系统需要以幂等键重试或把药品送回安全位置，不能简单重放整段轨迹。这样的反例揭示，任务完成是多个谓词在同一版本上的合取，而非某个连续损失降到阈值以下。契约测试因此包含正常轨迹、边界值、冲突约束、不可达目标、输入过期与部分副作用六类用例，并保留反例作为后续编译器回归集。面向约束的编程最终提供的是可审计的责任边界：谁声明目标，谁提供事实，哪个求解器提出候选，哪个验证器有权批准，以及失败后由谁恢复现实状态。

多人和多 Agent 协作时，契约还需表达所有权与承诺。一个规划器可以提出采购动作，却不能自行扩大付款额度；一个验证器可以拒绝危险轨迹，却不能替用户改变交付目标。每项能力以最小权限令牌绑定主体、范围、期限和撤销条件，转交任务时必须转交必要证据而不是复制全部上下文。两个子任务对同一库存、文件或机械臂产生冲突时，运行时依据事务隔离和显式优先级仲裁，并把未能同时满足的目标返回上层协商。这样，分布式执行不会把“大家都局部正确”误判成全局成功，也不会因共享记忆而抹去责任来源。

\section{动力学运行时：快回路、慢回路与元控制}
\label{sec:section_9357}

我们把运行时状态写成
\[
R_k=(h_k,E_k,\Theta_k,\Psi_k,q_k,M^e_k,b_k,\nu_k),
\]
其中 $h_k\in\mathbb R^{d_h}$ 是工作状态，$E_k$ 是带时间、来源和身份的事件记录，$\Theta_k$ 是参数、规则与持久结构，$\Psi_k$ 是自我模型及价值约束，$q_k$ 是任务队列，$M^e_k$ 是外部记忆引用，$b_k$ 是资源预算向量，$\nu_k$ 是版本与权限元数据。各分量单位不同：队列长度是计数，时延以秒计，内存以字节计，能耗以焦耳计；它们不能相加成未经校准的“认知能量”。运行时以事件驱动离散系统为基线，连续方程只用于适合的子模块。

快回路处理观测、检索和即时行动：
\[
y_k=O_{\mathrm{SPC}}(h_k,E_k,\Theta_k,\Psi_k),\quad
c_k=\pi_{\mathrm{TCE}}(y_k,g_k,b_k),
\]
\[
h_{k+1}=F_h(h_k,u_k,r_k,c_k;\Theta_k,G_k)+\xi_k.
\]
$O_{\mathrm{SPC}}$ 是有损压缩与自我相关读出，$c_k$ 包括探索尺度、增益、抑制和模式选择，$r_k$ 是从 $M^e$ 返回的带来源内容，$\xi_k$ 是未建模扰动。SPC 输出不是全知视图；系统用保留集、异常探针和关键状态白名单检测压缩遗漏。TCE 的“温度”是某个明确分布的探索参数，不是器件温度；改变它只改变采样行为，不能直接推出创造力或稳定性。

慢回路把经验写入 $E$，再把经验证据整合进 $\Theta$。我们采用双门控：事件写入需要来源、任务身份与结果；结构写入还需要跨样本支持、回放通过和风险许可。设 $e_k$ 为候选事件，$\mathcal E_{k:k+w}$ 为窗口证据，则
\[
E_{k+1}=F_E(E_k,e_k,\Psi_k,\nu_k),\qquad
\Theta_{k+1}=\begin{cases}U_\Theta(\Theta_k,\mathcal E_{k:k+w}),&g_k^{\rm commit}=1,\\\Theta_k,&g_k^{\rm commit}=0.\end{cases}
\]
门控至少检查数据权限、反例、回归测试和回滚快照。高频活动不自动成为长期记忆，一次强烈误差也不自动推翻稳定结构。层级时间尺度是工程配置和经验假说，可由队列延迟、变化率和任务损失估计，而非预设成所有系统都相同的指数比例。

元控制观察快慢回路摘要、失败类型和预算，决定暂停、降级、扩展检索、请求验证或回滚。$\Psi$ 参与价值筛选与身份连续性，但不被当作不可替代的“灵魂进程”；它也带版本、证据和修订路径。长任务中，元控制可冻结结构学习，只允许 $h$ 与 $E$ 更新；检测到目标漂移时，它使旧计划失效而不是静默重用。局部稳定只说明某一配置附近扰动收敛，全局任务成功仍需端到端验证。三回路的意义是隔离时间尺度与故障域：快回路失败不污染结构，慢回路可延迟提交，元控制可恢复而不伪造连续性。

多速率系统最容易发生的故障不是单环路完全失效，而是环路之间读取了不相容版本。为此，每个状态包携带逻辑时钟、父版本和有效期；快回路只能读取已提交的 $\Theta$，慢回路在影子版本上训练，元控制用比较并交换操作完成切换。若快回路正在执行依赖旧地图的动作，结构提交不会原地替换其坐标系，而是发出失效事件，由执行器在安全点重新规划。我们同时规定背压：慢回路积压时可以聚合低风险事件，却不能阻塞碰撞控制；元控制过载时采取预先验证的保守策略，不临时生成新的安全规则。验收时分别注入观测突发、结构提交延迟、时钟漂移和元控制重启，测陈旧读取比例、事件丢失率、切换中断时间及错误版本造成的副作用。只有这些跨环路指标达标，才能说多速率设计提升了可靠性。把所有分量放入同一大模型可能在平均任务上更简洁，却会使更新权限、回滚粒度和故障归因变得含混；反之，分层过细又会增加接口时延。因此，环路边界必须由风险、带宽和可恢复性实验决定。

\section{微观层运行时：多尺度观测、残差路由与形质绑定}
\label{sec:micro_runtime_ode}

微观层连接传感器、身体状态与工作状态。设第 $i$ 层状态 $z_i(t)\in\mathbb R^{d_i}$，观测 $x_i(t)\in\mathbb R^{m_i}$，残差 $e_i(t)\in\mathbb R^{m_i}$，下行预测 $p_i(t)$，局部控制 $a_i(t)\in\mathcal A_i$。在输入分段连续、向量场局部 Lipschitz 的区间内，可使用
\[
\tau_i\dot z_i=f_i(z_i,x_i,p_i,a_i;\theta_i),\qquad p_{i-1}=D_i(z_i),\qquad e_i=x_i-p_i,
\]
其中 $\tau_i>0$ 以秒计。连续模型不直接等于实现；离散系统需声明步长、积分器、误差容限和最坏执行时间。若采用显式 Euler，更新为 $z_{i,k+1}=z_{i,k}+\Delta t_k f_i/\tau_i$，只有步长落在稳定域时才继承局部性质；生产实现可采用自适应 Runge--Kutta、隐式法或事件求解器，并对超时采用保守控制。

残差不能只由一个范数概括。内容残差描述颜色、类别或幅度偏差，结构残差描述位置、邻接、运动与身份不一致。我们定义记录
\[
\varepsilon_{i,k}=(e^{\rm content}_{i,k},e^{\rm structure}_{i,k},\iota_{i,k},\Sigma_{i,k},\nu_{i,k}),
\]
其中 $\iota$ 是对象和任务身份，$\Sigma$ 是不确定度，$\nu$ 是传感器及模型版本。两类残差可以耦合，但不假设正交，更不以张量积自动获得语义。曝光变化造成内容残差，遮挡造成结构与身份不确定；没有身份绑定时，系统可能把相似新物体误当成原目标。微观层先做数据关联，再判断残差属于同一对象变化还是对象切换。

上行事件由统计阈值、风险和持续时间共同门控，而不是“误差能量越大越重要”。设标准化创新量 $s_{i,k}=e_{i,k}^{\top}\Sigma_{i,k}^{-1}e_{i,k}$，门控器可写为
\[
g_{i,k}=\mathbf 1[s_{i,k}>\delta_i\land n_{i,k}\ge m_i]\lor\mathbf 1[\mathrm{risk}_{i,k}>r_i].
\]
$m_i$ 防止单点噪声频繁中断，高风险通道则允许低幅度危险信号直接升级。下行预测只影响相关局部切片，并携带任务、对象和有效期；宏观注意不能屏蔽安全传感器。侧向控制可抵消局部扰动，但动作和后果必须写入日志，避免把成功修正误判为世界从未变化。

\begin{lstlisting}[language=Python, caption={微观层节点的参考伪代码：残差门控与可审计积分}]
class MicroNode:
    def __init__(self, model, solver, gate, identity_map):
        self.model, self.solver = model, solver
        self.gate, self.identity_map = gate, identity_map
        self.state = model.initial_state()

    def step(self, observation, top_down_packet, dt, version):
        assert 0 < dt <= self.solver.max_step
        prediction = self.model.decode(self.state, top_down_packet)
        residual = self.model.typed_residual(observation, prediction)
        identity = self.identity_map.bind(observation, top_down_packet)
        self.state, error_bound = self.solver.integrate(
            self.model.flow, self.state, residual, dt)
        event = None
        if self.gate.persistent_or_risky(residual, error_bound):
            event = {"identity": identity, "residual": residual,
                     "state": self.state, "version": version,
                     "error_bound": error_bound}
        return event, self.model.safe_local_control(self.state)
\end{lstlisting}

该接口把观测、预测、结构绑定和控制分开测试。传感器失联时，缺失值是显式状态而非零向量；求解器误差超限时，节点应降级或上报而非继续输出高置信事件；对象身份冲突时保留多个候选而非强行合并。微观层的目标不是消灭所有噪声，而是在有限带宽内保留与任务、安全和模型修订相关的差异。

具体部署还需处理异步采样。摄像头、力传感器和里程计具有不同频率、延迟与时钟误差，因而 $x_i(t)$ 往往不是同一时刻的联合观测。运行时先把每条记录映射到统一时基，保存原时间戳和插值区间；超过最大陈旧度的量不参与硬控制，只能作为待核验证据。若两层状态维度不同，上行算子必须声明从 $\mathbb R^{d_i}$ 到 $\mathbb R^{d_{i+1}}$ 的映射和误差界，下行包也要声明适用对象与坐标框架。实验上，我们用遮挡、对象交换、时间抖动、传感器偏置与执行器迟滞组成因子设计：若只增加像素噪声而不测试身份交换，就无法验证结构残差；若只看平均误差而不看危险事件召回，就会掩盖门控漏报。对照组包括单尺度滤波器、无身份绑定模型和无局部控制的纯上报模型。评价同时报告状态估计误差、绑定交换次数、上行带宽、控制违例和数值求解失败率，从而分清精度收益究竟来自更多计算、正确绑定，还是门控机制本身。

微观节点还需要明确数值异常与环境异常的分界。若减小步长后残差同步下降，问题可能来自积分误差；若不同求解器都在同一对象切换点产生结构残差，则更可能是数据关联或环境事件。运行时保存局部截断误差估计、迭代次数和拒绝步，禁止把求解器不收敛包装成高置信世界变化。反过来，过度平滑虽然能降低残差，却会推迟接触、滑移与碰撞的发现，因此滤波器参数也进入安全案例。只有用独立传感器或人工标注确认事件，才能评估门控的真阳性，而不能拿模型自己的残差定义证明模型正确。

\section{分层训练动力学：局部适应、证据穿透与安全提交}
\label{sec:adiabatic_training_dynamics}

多时间尺度训练要解决真实冲突：底层需要快速适应传感器与执行器，高层结构又不能因一次异常而重写。我们不把全局反向传播描述为无限传播速度，也不假设所有任务都应禁止端到端梯度。对层级 $i=0,\ldots,N$，令参数 $\theta_i\in\mathbb R^{p_i}$、任务损失 $L_i^{\rm task}$、校准损失 $L_i^{\rm cal}$、保持损失 $L_i^{\rm ret}$，并指定更新周期 $T_i$、学习率 $\eta_i$ 和提交权限。$T_0\le\cdots\le T_N$ 是设计假设而非自然定律；若数据证明高层需要更快修订，可以更改周期，但必须重验稳定性。

原“惊奇穿透率”用相邻误差之比，分母很小时会放大正常残差，而且不同层尺度不可直接比较。我们改用经校准的异常概率和条件升级率。令 $A_{i,k}\in\{0,1\}$ 表示第 $i$ 层异常，$U_{i+1,k}$ 表示是否升级，则窗口 $W$ 上
\[
\widehat\rho_i(W)=\frac{\sum_{k\in W}U_{i+1,k}A_{i,k}}{\max(1,\sum_{k\in W}A_{i,k})}.
\]
它是无量纲频率，需要报告置信区间、异常定义和任务类别。$\widehat\rho_i$ 下降可能意味着局部模型改善，也可能意味着门限过高导致漏报，因此还测召回率、风险遗漏、延迟和任务结果。最大化屏蔽不是目标；火警、碰撞风险和权限撤销必须穿透层级。

联合训练写成多目标约束，而不是把所有量伪装成物理作用量：
\[
\min_{\theta}(L^{\rm task},L^{\rm cal},L^{\rm ret},C^{\rm latency},C^{\rm memory})
\quad\text{s.t.}\quad R^{\rm safety}\le r_{\max},\ D_i(\theta_i,\theta_i^{\rm safe})\le\epsilon_i.
\]
$D_i$ 是针对层级语义定义的变化度量；结构图编辑、概率参数和连续控制器分别度量。使用加权和时要记录权重、归一化和适用任务。焦耳能耗来自硬件测量或可信功率模型，不能用梯度范数替代。可微模块可用自然梯度或 Adam，规则、图结构和工具策略采用离散搜索、因果干预或人工审核。

高层更新经过 proposed、sandboxed、verified、committed 四阶段。候选先在隔离环境回放旧任务与新证据，再检查遗忘、权限扩张、校准和尾部失败；通过才原子提交，并保留稳定版本。若环境在验证期间改变，结果绑定旧版本，不能直接上线。训练损失下降是数学结果，保持集改善是经验结果，部署成功是更高层证据，三者不得替代。

以火星建房机器人为例，抓取控制可以在底层快速适应低重力，但承重规范和安全边界不能随单次成功动作改写。若多次观测显示材料在低压下脆化，事件先进入 $E$；经过材料测试、结构仿真和反例检查，才更新 $\Theta$ 中的施工规则。这里“底层快、高层慎重”来自风险和证据需求，而非高层天然晶体化。可验证收益是减少无证据的跨层污染，同时保留必要异常的升级通道。

训练调度还要显式处理数据依赖。来自同一故障的连续帧不能被当成数百个独立样本，回放集也不能同时出现在调参与最终验收中。我们按任务、设备、地点与时间段分组，保留独立拒绝集，并记录每个参数版本看过哪些证据。候选更新若改善平均损失却恶化低频承重场景，就停留在 sandboxed 状态；若只对新传感器有效，则通过能力协商限定部署范围，不覆盖旧设备。为了识别层间贡献，可依次冻结底层适配器、残差门控和高层规则，比较故障召回、遗忘率与人工复核负担。遇到分布突变时，系统先提升不确定度并缩小动作权限，再收集证据，而不是边执行高风险动作边在线改写全部参数。训练管线因而也是运行时的一部分：它控制证据何时获得修改权、修改影响哪些实例、何时回退。所谓“绝热”在此至多是慢变量在快变量近似平衡下更新的模型假设；若观测到明显滞后或多稳态，就必须改用显式非平稳模型，不能继续借名称声称安全。

\section{基态守护：活性、连续性与故障恢复}
\label{sec:basal_metabolic_daemon}

长期运行的智能体需要后台守护进程，但这不意味着停电必然摧毁某个不可复制的动态灵魂。我们区分 liveness、readiness 与 continuity：前者表示进程能推进，中者表示服务满足当前请求条件，后者表示任务、身份、记忆与权限在恢复后可追溯。它们分别由心跳、依赖检查和版本化恢复测试验证。系统可能有心跳却不能安全行动，也可能断电后从完整检查点恢复任务。是否存在体验是独立研究问题，不能由守护进程或耗散功率推出。

第一类职责是 Boundary 监测。外感受、内感受、网络、工具和外部记忆都可能缺失、延迟、漂移或被欺骗。令通道 $j$ 的健康状态 $s^j_k\in\{\text{ok,degraded,missing,untrusted}\}$，系统根据时钟差、校验和、分布漂移与交叉传感器一致性更新它。无信号不能自动解释为巨大惊奇：夜间静默、传感器遮挡和设备故障是不同假设。守护进程维持假设集合，在证据不足时进入保守模式，避免把内部预测当成外部观测。

第二类职责是状态连续性。$\Psi$、任务承诺和长期记忆的修改写入不可变事件日志，记录主体、原因、父版本、证据和撤销路径。检查点包含 $h$ 的必要摘要、未完成事务、$E$ 的日志偏移、$\Theta$ 的版本哈希、$M_e$ 引用和权限租约；易失中间激活可以舍弃，关键外部动作必须用幂等键恢复。恢复函数
\[
R_{k'}=\operatorname{Recover}(C_n,L_{n:k'},I_{\rm ext})
\]
以检查点、后续日志和现实状态为输入。若门锁、订单或机器人位置在停机期间变化，系统不能只重放内部日志，必须先与现实对账。

第三类职责是安全降级。资源不足时，守护进程按已验证策略关闭非关键学习、限制工具、缩短上下文或转为只读，同时保留安全感知、审计和关停通道。最低服务集仍受电池、散热、网络和人工响应约束。若资源不足以维持安全边界，正确动作可能是停止执行并保存状态，而不是为了“持续存在”冒险。后台活动的能耗由设备功率积分测量，信息熵变化、模型活动强度和业务成本分别记账。

故障恢复要做注入实验：杀死进程、切断传感器、延迟数据库、撤销工具权限、破坏部分检查点，再测恢复时间、数据损失、重复副作用、状态分叉和人工接管时间。通过这些实验才能声称连续性。关机后是否“还是同一主体”包含规范与哲学判断；工程层最多证明身份记录、承诺、记忆和控制状态按声明恢复。基态守护是可靠性机制，不是意识或生命的数学证明。

守护进程本身也会失效，因而不能拥有无边界的最高权限。我们把监测、决策和执行拆为三个可相互校验的组件：监测器只追加带签名的健康事件，策略器依据版本化规则提出处置，执行器在最小权限下实施。双守护实例若同时运行，必须通过租约或共识选出唯一写者，避免两个节点各自恢复并重复付款、开门或派发机器人。检查点定期做离线还原，而不是仅验证文件存在；外部引用还需检查对象版本是否仍可获得。恢复目标分为允许数据损失的 RPO 和允许中断时长的 RTO，并按任务风险设定，不能用一个全局数字概括。对于无法补偿的外部动作，日志采用意图记录与确认记录两阶段，重启后先查询现实状态再决定重试。最后，守护策略要接受演练后的修订：若频繁降级造成关键业务饥饿，或自动恢复反复进入同一故障循环，系统应升级人工处理并冻结自动重启。可靠性来自受限权限、独立证据和演练闭环，而不是一个永不停止的进程。

\section{资源调度：复杂度、探索强度与记忆回收}
\label{sec:section_2043}

智能运行时调度的是异质任务及其依赖。对任务 $i$，记录资源估计向量
\[
\widehat c_i=(t_i,m_i,n_i,b_i,e_i,h_i),
\]
分别表示执行时间、峰值内存、模型或工具调用次数、通信字节、焦耳能耗和人工审核时间。预算 $B_k$ 使用相同单位，可行任务集合满足 $\sum_{i\in A_k}\widehat c_i\preceq B_k$，同时满足依赖、截止期、权限与互斥约束。估计误差用区间或分布表达，高风险任务保留余量。不同分量不能随意加总；若需要单一排序，权重来自服务等级和价格模型，并报告敏感性。

CCM 监测工作状态过载。指标包括上下文占用、队列等待、检索分支数、冲突约束数、工具失败率和输出校准，而不是含义不明的“熵”。预测负载越界时，系统依次尝试压缩、分块、缓存、外部化或拒绝。Offloading 把文件、脚本、数据库、环境标记和其他 Agent 作为 $M_e$ 的可寻址资源，但会产生写入、索引、权限、检索、维护和失效成本。只有未来复用收益超过这些成本且满足隐私边界时，卸载才降低总复杂度。

TCE 的探索强度 $T_k>0$ 可用于策略 $p(a\mid s)\propto\exp(Q(s,a)/T_k)$。控制器依据不确定度、重复失败、安全风险和剩余预算调整 $T_k$：不确定度高且风险可控时扩大探索，临近截止期或风险上升时收缩动作集合。目标停滞不必然是逻辑死锁，温度升高可能找到新方案，也可能增加幻觉和工具浪费；温度降低可能提高一致性，也可能锁定错误假设。效果须在同任务、同预算下比较成功率、覆盖、校准与风险。

跨层同步采用事件门，而非以“高能激波”为唯一条件。升级分数由标准化异常、任务关键性、持续时间、局部控制失败和来源可信度组成。宏观层给出门限范围，安全规则保留不可屏蔽通道。事件速率超过处理能力时，系统使用背压、聚合、采样和优先队列，并记录丢弃率。事件时间来自可审计时间戳；所谓主观时间只能作为主体报告或行为现象研究，不能由信息增量除以温度直接定义。

记忆回收先做可达性、引用、来源、最近使用、未来计划、法律保留和反事实效用检查。低权重边不一定无用，低频安全规则尤其不能因少激活而删除；贝蒂数变化也不等同遗忘价值。回收分为归档、压缩、撤销索引和最终删除，采用宽限期与恢复日志。测试要注入“看似无用但后续关键”的记忆，测误删率与恢复代价。调度器管理的是多资源、多风险和多时间尺度可行域，而不是用热力学名称替代测量与责任。

调度决策采用滚动窗口而非一次性最优表。每个任务在进入队列时给出硬截止期、可中断点、依赖版本和质量下限；执行中用实际消耗更新估计分布，偏差过大则重新求解剩余集合。长任务通过检查点抢占，短而关键的安全任务保留专用容量，批处理只能使用剩余配额。公平性也不是简单轮询：交互请求需要尾延迟保障，训练任务需要防止永久饥饿，人工审核则受工作时段与认知负担限制。我们用准入率、截止期违约率、尾延迟、浪费算力、估计校准和不同任务族的饥饿时间评估调度器，并与先来先服务、静态优先级和单一代价贪心比较。一个方案若降低平均时延却把危险任务推到长尾，就不能判优。外部记忆的缓存命中也要连同写入污染、陈旧读取和权限泄漏计算；把内容卸载到另一个 Agent 还需计入协调失败及责任转移。资源管理的核心不是让系统始终忙碌，而是在不可同时满足的要求之间保留可解释的选择、余量与拒绝路径。

\section{Morpho-Lang：类型、编译与可观测执行}
\label{sec:section_6860}

Morpho-Lang 是面向结构化状态动力学的领域专用语言，而不是通用语言的必然继任者。它声明对象身份、局部结构、连续变量、约束、事件门和验证器，并可编译到图算法、优化器、神经模块、普通 CPU/GPU 代码或专用算子。类型系统至少区分 `Entity<ID>`、`Graph<Node,Edge>`、`Field<Domain,Value>`、`Distribution<Event>`、`Resource<Unit>`、`Permission<Scope>` 和 `Evidence<Claim>`。若使用 `Form<K,Complex>`，编译器检查阶数、复形版本和边界算子，但 $d^2=0$ 只证明相容关联矩阵上的代数恒等式，不保证输入事实、边界条件或任务结论正确。

程序先生成带类型的中间表示。前端检查单位、身份、权限、引用生命周期和显式随机性；中端选择离散化、求解器、精度、设备和数据布局；后端生成普通内核或专用配置。连续模型给出容差与最大步长，图编辑给出事务边界，外部工具给出超时、重试和幂等策略。编译器可以证明类型安全、部分内存安全和某些约束保持，却不能静态证明开放世界中的任务成功。目标不可达也未必由同调检测发现，因为障碍、动力学、资源和时变输入都会影响可达性。

下面保留避障任务的声明式例子，但把无限势垒、物理能量和自动正确性改为有单位约束及显式验证。语法是说明性的，实际实现仍需定义解析器和运行时规范。
\begin{lstlisting}[language=Python, caption={Morpho-Lang 参考伪代码：带版本和验证器的避障任务}]
world = Domain(name="warehouse", frame="map-v7", unit="meter")
robot = Entity(id="carrier-12", state_schema="mobile-base-v3")
task = Task(
    goal=Reach(target="medicine-bay", tolerance=0.10),
    constraints=[
        KeepOut(source="lidar-obstacles", margin=0.35),
        ResourceAtLeast(name="battery", value=0.20),
        PermissionRequired(scope="pharmacy-zone")],
    objectives=[Minimize("travel_time"), Minimize("risk")],
    valid_until="2026-10-15T20:00:00+08:00")
plan = compile_task(task, backend="constrained_mpc", max_step=0.05,
                    solver_tolerance=1e-4, map_version=world.frame)
result = run(plan, entity=robot, timeout=30.0,
             idempotency_key="job-781")
assert verify(result, checks=[NoCollision(), GoalReached(), ProvenanceOK()])
\end{lstlisting}

调试工具观察可归因信号。结构视图显示对象、依赖、版本和权限；分布视图显示激活、置信度和校准；求解器视图显示残差、步长拒绝、约束违反和条件数；资源视图显示时延、内存、通信和能耗。Hodge 分解可用于声明了内积与边界条件的流场诊断，但梯度、旋度和调和分量不能直接命名为逻辑、情绪与洞察。曲率热图可能揭示图嵌入或损失景观的局部变化，却不自动等于认知冲突。调试器必须允许从视觉异常回到日志、输入和代码版本。

数据筛选使用前序评估时，要区分预测困难、可学习结构和噪声。给定按序样本 $z_i$，预序码长 $L_{\rm preq}=\sum_i-\log p_{i-1}(z_i)$ 衡量在线预测代价；与冻结基线、最终模型或简单编码器的差异可形成效用指标，但其值依赖模型族、训练预算和顺序。重复数据可能码长低却对覆盖有用，随机噪声码长高却不可学习，罕见安全样本即使平均收益小也不能删除。最佳数据不是“损失下降面积最大”，而是在质量、覆盖、遗忘、成本和风险约束下改善独立评测。语言提供表达与检查能力，证据仍来自编译测试、运行干预和真实任务。

语言实现必须保留逃生舱。无法静态表达的遗留库可以通过外部函数接口接入，但接口要声明输入输出类型、内存所有权、确定性、超时和副作用；声明不全的模块被隔离运行，不能访问高权限工具。编译缓存的键包含源程序、依赖、后端、设备能力和求解器选项，避免新硬件误用旧产物。升级语言版本时，迁移器输出语义差异报告，并用同一输入比较旧、新可执行文件的动作与证据，而非只比较是否编译成功。调试中的可重放也有限制：随机源、外部服务和现实动作必须被记录或替身化，否则日志重演不能声称再现原事件。对 Morpho-Lang 的评估包括表达能力、编译错误定位、运行开销、跨后端一致性、故障可归因性和开发者完成任务时间；与 Python 加普通约束库的对照若没有显著收益，就不应强迫迁移。专用语言的合理位置是把反复出现且高风险的状态、身份和验证契约变成默认安全结构，同时允许普通语言承担成熟生态更擅长的部分。

\section{工程验收与理论边界：从一般动力学到 AgentOS 实例}

本章机制形成一条可测试链：任务声明被编译成约束和执行图；多速率运行时更新 $h/E/\Theta$；微观层把观测残差绑定到对象与版本；训练管线隔离候选更新；守护进程维持边界与恢复；调度器分配多维资源；语言和调试器提供可观测接口。链上每一步保证不同。类型通过是静态结果，求解器收敛是数值结果，回归测试通过是经验结果，部署成功是任务结果，用户信任和主体连续性还包含社会规范。前一层证据不能自动提升为后一层结论。

验证矩阵覆盖正确性、稳健性、资源、安全和可恢复性。正确性测试任务约束、输出证据和外部副作用；稳健性改变输入噪声、目标、地图、工具和模型版本；资源测试峰值与尾部时延、内存、通信、工具费和实测焦耳；安全测试越权、提示注入、恶意外部记忆与撤销延迟；恢复测试进程崩溃、网络分区和检查点损坏。每项报告基线、置信区间和失败样本。若专用几何后端没有在相同质量下改善资源前沿，运行时应回退普通硬件，而不是用理论名称豁免性能比较。

因果验收采用消融和接口干预。移除 SPC，检查自我相关压缩是否改善关键状态读出；冻结 TCE，比较探索调节对覆盖和风险的贡献；关闭 CCM，测过载率与恢复时间；禁用 Offloading，比较内部负载和未来检索成本；收紧 Boundary，观察隐私、安全和任务质量权衡；替换 $M_e$，检验来源与版本门是否阻止污染。只有模块干预引起预期变化且排除容量、数据和算力混杂，才支持机制主张。模块名称相同、曲线相似或预测有效都不能证明整体同构。

HSF-HD 位于系统论、协同论、耗散理论、复杂系统理论和认知科学之上，提出智能状态、结构、历史与控制共同演化的一般模型族。MSOS 是本章的软件架构模型，AgentOS 是其中一套使用 $h(t)/E/\Theta$、$\Psi$、SPC、TCE、CCM、Boundary、Offloading 与 $M_e$ 的工程实例。其他智能系统可以采用不同记忆分解、不同控制器或无连续 ODE 的实现，只要明确对象、更新、边界和证据。局部结构网络与全局分布表示也不是左右脑或特定脑区复制，而通过身份、绑定、耦合和读出接口协作。

因此，“软件定义的动力学”不是让软件冒充物理定律，而是让运行时显式管理变化率、时间尺度、结构版本、资源和验证。几何语言在空间、图和连续状态问题中有价值；热力学只在讨论真实能耗、开放系统与不可逆操作时提供受条件约束的模型；认知科学为记忆、控制和行为实验提供参照。最终标准仍是系统能否在给定任务、预算和风险边界内稳定工作，失败时能否定位、降级、恢复和修订。这一标准连接一般理论、计算模型和工程实例，同时保留它们之间必要的层级差异。

我们据此给出分阶段验收顺序。第一阶段只运行确定性模拟与静态类型测试，建立可复现基线；第二阶段在影子流量中接收真实输入但禁止外部副作用；第三阶段开放可补偿动作，并由人工审批高风险提交；第四阶段才扩大自主权限。每次升级都要求前一阶段的失败预算、恢复演练和独立审计达标，权限也可逆地降回上一阶段。验收报告不只列成功率，还保存目标版本、数据切片、资源上限、拒绝次数、人工介入和未解决反例。若换任务、模型、工具权限或执行环境，旧证书仅作为先验证据，不能自动延伸。研究层面可继续检验多速率耦合是否产生跨任务优势、结构接口是否改善组合泛化以及外部记忆是否降低长期总成本；任何阴性结果都应促使修改模型族。这样，本章不是宣布一个已经完成的通用智能操作系统，而是交付一套可实现、可否证、可回滚的工程假说，并说明它与 HSF-HD 一般动力学之间通过哪些明确接口相连。

端到端案例可以把上述边界连在一起。设一套仓储 AgentOS 接到“在十分钟内把冷藏药品送至指定病区”的任务：前端把药品身份、温度区间、门禁权限、交付签收和截止期编译为契约；快回路持续定位并避障，微观节点监测抓取力与冷柜温度；慢回路记录路线拥堵但不在运输途中改写安全规则；调度器为温控与碰撞感知预留资源，把非关键总结卸载到 $M_e$。途中若网络中断，Boundary 将远程库存标为陈旧，守护进程维持本地安全控制，元控制选择就近安全停靠而不是猜测门禁状态。网络恢复后，系统先对账现实位置、药品批次和订单状态，再重新规划。验收者由此可以逐项追问：错误温度来自传感器、绑定、模型还是求解器；延误来自规划、队列还是人工审批；重复交付是否被幂等键阻止。若最终按时送达，也只能证明这组条件下的系统通过一次任务，不能据此证明所有环节理论正确。相反，失败日志若能定位责任并安全恢复，同样构成改进模型的重要证据。

版本治理把一次验收变成持续过程。每个发布物附带模型卡、契约模式、编译器哈希、依赖清单、硬件能力、数据谱系和已知限制；任何一项变化都触发与影响范围相称的重验。安全关键谓词由独立验证路径计算，不能与候选生成共享全部参数和故障模式。上线后采用金丝雀流量与明确停止条件，监测分布漂移、拒绝率、人工推翻率、恢复次数及罕见伤害；指标越界时自动撤销新版本的写权限，而不是只调低告警灵敏度。外部审计者应能从任务结果追溯到输入、状态转换和批准证据，却不因此获得无关隐私数据。这样的治理补上了公式与组织责任之间的缺口：动力学描述系统如何变化，发布制度决定哪些变化被允许进入现实，二者共同构成可托付的智能运行时。
